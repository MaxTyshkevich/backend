# Профили, комментарии и демонстрационные данные

## Связи

`users` → `profiles`: один профиль на пользователя, `profiles.user_id` — первичный и внешний ключ. `users.name` остаётся единственным источником имени. При регистрации профиль создаётся вместе с пользователем; для старых аккаунтов — при первом сохранении. GET не записывает данные.

`products` → `comments` и `users` → `comments`: один товар/автор имеет много комментариев. Удаление товара или пользователя удаляет связанные комментарии; удаление пользователя также удаляет профиль. Индексы поддерживают выборку комментариев товара и автора. Комментарии не содержат оценку и не меняют `products.rating`.

## Доступ

Все изменения требуют действующей cookie-сессии и `X-Requested-With: microfronts`; Origin проверяется существующим CsrfGuard. Нет сессии — 401, нарушен CSRF — 403, неверный ввод — 400. Неизвестные поля запрещены. Владельца сервер получает из сессии; клиент не задаёт `userId`, роль и служебные поля.

## Профиль

- `GET /api/profile/me` — собственный профиль, 200.
- `PATCH /api/profile/me` — частичное изменение собственного профиля, 200.

Ответ: `{ id, name, profile: { bio, avatarUrl, createdAt, updatedAt } }`. Даты — ISO 8601. Если старый пользователь ещё не сохранил профиль: `bio: ""`, `avatarUrl: null`, обе даты `null`. Ответы имеют `Cache-Control: no-store`. Email, хеш пароля и данные сессии не возвращаются.

PATCH принимает только `name` (3–20 символов, как при регистрации), `bio` (0–2000) и `avatarUrl` (HTTPS URL до 2048 символов). Строки обрезаются по краям. Пропущенные поля сохраняются; `bio: ""` очищает биографию, `avatarUrl: null` очищает аватар. `name: null` и `bio: null` запрещены. Пустой PATCH допустим и создаёт отсутствующий профиль. Имя обновляется атомарно с профилем и видно в `/api/auth/me` и авторстве комментариев. Загрузки файлов и публичного API профилей нет.

## Комментарии

| Метод и путь | Результат |
| --- | --- |
| `GET /api/products/:productId/comments?page=1&limit=20` | Публичное чтение, 200: `{ items, page, limit }` |
| `POST /api/products/:productId/comments` | Создание от имени текущего пользователя, 201 |
| `PATCH /api/comments/:id` | Изменение собственного комментария, 200 |
| `DELETE /api/comments/:id` | Удаление собственного комментария, 204 без тела |

POST/PATCH принимают `{ text }`: непустой текст до 5000 символов после обрезки по краям. Комментарий возвращается как `{ id, productId, text, createdAt, updatedAt, user: { id, name } }`. Email и профиль автора не раскрываются. Текст хранится как обычный текст; клиент должен отображать его без интерпретации HTML.

Сортировка — сначала новые, затем ID по убыванию при одинаковой дате. `page` — целое 1–100000, `limit` — целое 1–100, по умолчанию 1 и 20. За пределами списка возвращается пустой `items`. При добавлении новых комментариев между запросами страницы могут сдвигаться. Полный список не включается в ответ товара.

Неизвестный товар — 404; отсутствующий или чужой комментарий — 404, в том числе для ADMIN. Некорректный UUID комментария — 400. Модерация и ответы на комментарии в этот этап не входят.

## Миграция и заполнение

`20261031135450_add_profiles_comments` сгенерирована Prisma через `db:migrate -- --name add_profiles_comments --create-only`. Она добавляет таблицы, индексы и внешние ключи без изменения существующих записей.

```powershell
npm run db:deploy
npm run db:generate
npm run db:seed
```

Обычный seed добавляет три категории и 30 товаров, включая прежние `keyboard`, `monitor`, `dock`. Пользователей он не создаёт. Существующие записи и ручные изменения сохраняются.

Для демонстрационного наполнения **локальной** `microfronts` задай `DEMO_PASSWORD` (12–128 символов) в локальном `.env` или окружении, затем:

```powershell
npm run db:seed:demo
```

Команда разрешает только loopback-адрес и имя БД `microfronts`. Она сначала запускает seed каталога, затем в отдельной транзакции добавляет пять пользователей `demo1@example.test` … `demo5@example.test`, пять профилей и 60 комментариев — по два на товар. Все аккаунты имеют роль USER и общий заданный пароль, сохранённый только как scrypt-хеш. Аватары изначально пустые.

Постоянные ID предотвращают дубли. Существующие имена, пароли, профили и комментарии не перезаписываются; смена `DEMO_PASSWORD` при повторном запуске не меняет пароли созданных аккаунтов. Конфликт email с другим ID прерывает транзакцию демонстрационных данных. Каталог к этому моменту уже мог быть дополнен. Сессии и корзины не затрагиваются. Скрипт восстанавливает отсутствующие демонстрационные записи, поэтому удалённые вручную demo-комментарии появятся при новом запуске.

В облаке применяются только миграции штатным pre-deploy. Демонстрационные пользователи и комментарии автоматически не создаются; заполнение облачной БД требует отдельного согласованного шага.

## Проверки

`npm test` проверяет миграции без demo-записей, повторное заполнение и сохранность изменений на изолированной `microfronts_test`. `npm run test:e2e` проверяет доступ, CSRF, валидацию, пагинацию, редактирование профиля и запрет изменения чужих комментариев. Наборы запускаются последовательно.
