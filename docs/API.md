# HTTP API

## Каталог

`GET /api/products` читает каталог из PostgreSQL. Товар содержит поля `description`, `rating` (0–5, `null` — оценок пока нет), `createdAt` и `updatedAt` (даты ISO 8601). Рейтинг пока хранится как значение; сбор пользовательских оценок не реализован. Дата создания заполняется автоматически, дата изменения обновляется Prisma при изменении товара. При прямом SQL-обновлении дату изменения нужно задавать явно. Цены корзины также берутся из БД; пока поддерживается USD.

Категории хранятся в `categories` (`id`, `name`, уникальный `slug`). Каждый товар относится к одной категории через `categoryId`; удаление используемой категории запрещено внешним ключом. Значение по умолчанию — `other`: перед созданием товара без явной категории она должна существовать. Данные можно редактировать через `npm run db:studio`.

- `GET /api/categories` — категории, включая пустые.
- `GET /api/products` — все товары, массив с `categoryId` и `category: { id, name, slug }`.
- `GET /api/products?category=peripherals` — фильтрация по slug; пустая существующая категория возвращает `[]`, неизвестная — 404, некорректный/повторённый параметр — 400.
- `GET /api/products/:id` — полный товар с описанием, рейтингом, датами и категорией; неизвестный ID — 404. ID остаются строками (например, `keyboard`).
- `POST /api/products` — создание только для ADMIN с действующей cookie-сессией и CSRF-заголовком. SessionGuard заново читает пользователя и роль из БД, RolesGuard проверяет ADMIN; если передан X-Session-User, он должен соответствовать пользователю сессии. Без сессии — 401, без роли или CSRF — 403. Публичное чтение не требует входа.

Создание принимает только `{ id, title, description, priceMinor, categoryId }`: уникальный ID из строчных латинских букв, цифр и дефисов (1–100 символов), название 1–200, описание 1–10000, целая цена 0–2147483647 в центах и ID существующей категории (1–100 символов). Строки обрезаются по краям; пустые и лишние поля отклоняются. Валюта USD, рейтинг null и даты задаются сервером. Ответ 201 содержит полный товар в формате GET; 400 — неверные данные/категория, 409 — занятый ID. Редактирование и удаление не реализованы.

## Авторизация и доступ

Auth: GET /api/auth/me, POST /api/auth/register, /api/auth/login, /api/auth/logout. Сессия действует семь дней. Регистрация принимает name, email, password (12–128 символов). При входе и регистрации гостевая корзина остаётся отдельной: переданный X-Cart-Key сейчас не запускает её перенос. Метод `CartService.mergeGuest` существует, но эти HTTP-маршруты его не вызывают.

Используй same-origin /api proxy на frontend: он должен передавать Cookie, Set-Cookie и Origin. CORS_ORIGINS содержит точные разрешённые origins. Мутации требуют X-Requested-With: microfronts. Cookie — HttpOnly, SameSite=Lax, Secure в production. COOKIE_SECURE=false предназначен только для локального HTTP Docker. X-Session-User проверяет ожидаемую личность, а не даёт доступ.

Ограничения входа: 10 попыток на email и 40 на IP за 15 минут. За reverse proxy настрой доверенную топологию до использования IP-лимита как персонального; автоматически доверять любому X-Forwarded-For нельзя.

Register возвращает 201 и `{ success: true }`, login/logout — 200 и `{ success: true }`. GET /api/auth/me возвращает `{ user: { id, email, name, role } }` либо `{ user: null }`. Auth-ответы имеют `Cache-Control: no-store`; cookie действует для `/api`.

Роль при регистрации — USER. Публичного API назначения ролей нет.

## Корзина

| Метод и путь | Назначение |
| --- | --- |
| GET /api/cart | Прочитать корзину |
| POST /api/cart/items | Добавить `{ productId, quantity }`, ответ 201 |
| PATCH /api/cart/items/:id | Задать `{ quantity }`, ответ 200 |
| DELETE /api/cart/items/:id | Удалить позицию, ответ 200 |

Количество — целое число 1–99; суммарное количество позиции не превышает 99. Ответ: `{ items: [{ productId, title, priceMinor, quantity }], totalMinor, currency, revision }`. Цена берётся из БД, валюта USD.

Пользователь определяется по cookie; гостю нужен `X-Cart-Key` с UUID v4. При несовпадении `X-Session-User` с пользователем сессии (либо `guest`) возвращается 401. Неверный гостевой ключ — 400; уже перенесённая гостевая корзина — 410. Перенос доступен только как операция сервиса, HTTP-вход и регистрация его не вызывают.

## Проверка доступности

- `GET /` — `Hello World!`.
- `GET /health` — `{ status: "ok" }`, без обращения к БД.
- `GET /api/health` — проверяет PostgreSQL; `{ status: "ok", storage: "postgresql", contractVersion: 2 }`. Используется Railway.
